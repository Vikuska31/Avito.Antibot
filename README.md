# Avito.Antibot
# Описание решения

## 1. Постановка

Единица классификации — `cookie_id`. Для каждой cookie строятся признаки только по событиям,
для которых выполняется:

`window_start_ts <= event_ts < window_end_ts`.

Модель выдаёт вероятность положительного класса (`target=1`). В `submission.csv` сохраняются
`cookie_id` из `test.csv` и непрерывный `score` от 0 до 1.

## 2. Предобработка

- События соединяются с метаданными cookie.
- События вне суточного окна не используются.
- Пропуски в агрегированных числовых признаках заменяются нулём.
- Сырые строки User-Agent не передаются в модель как текст: из них извлекаются компактные
  индикаторы платформы/браузера/мобильного клиента и доли таких событий.
- Для нескольких категориальных полей дополнительно используется наиболее частое значение
  внутри окна (`mode_*`).

## 3. Признаки

Используются несколько групп признаков:

1. **Интенсивность:** число событий, доли разных типов событий.
2. **Разнообразие поведения:** число уникальных объявлений, категорий, локаций, поисковых
   запросов, страниц выдачи и т.д.
3. **Временное поведение:** минимальный/медианный/средний/максимальный интервал между
   событиями, доли очень коротких интервалов, длительность активности, число сессий.
4. **Последовательность:** доля одинаковых событий подряд и число различных переходов
   между типами событий.
5. **Поиск:** статистики номера страницы, длина и количество слов поискового запроса.
6. **Курсор:** наличие координат и статистики перемещений курсора.
7. **User-Agent:** компактные индикаторы desktop/mobile, браузера, ОС и характерных
   технических токенов.
8. **Возраст cookie:** время от создания cookie до начала окна.
9. **Недельная сезонность:** день недели начала окна. День месяца не используется, чтобы
   не заставлять модель экстраполировать конкретные календарные даты из train в test.

## 4. Модель

Используется `CatBoostClassifier` локально, без внешних API и без больших языковых моделей.

Параметры:

- `iterations=800`
- `depth=7`
- `learning_rate=0.03`
- `l2_leaf_reg=5`
- `loss_function=Logloss`
- `random_seed` из `{0, 42, 123}`

Итоговый score — среднее трёх предсказаний. Это снижает зависимость результата от
одного случайного seed.

## 5. Валидация

Случайное перемешивание не используется, потому что тестовое окно идёт после train по времени.
Проверялись временные срезы:

| Validation window | Cookies | Боты | P@R>=0.70 | PR-AUC | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| 2026-04-13 ... 2026-04-15 | 2470 | 188 | ~0.76 | ~0.79 | ~0.94 |
| 2026-04-16 ... 2026-04-17 | 1453 | 126 | ~0.83 | ~0.78 | ~0.93 |
| 2026-04-18 ... 2026-04-19 | 1238 | 94 | ~0.69 | ~0.77 | ~0.94 |

Значения приведены как локальная диагностика; на небольших временных срезах P@R заметно
колеблется из-за небольшого количества положительных объектов.

В качестве контрольного baseline использовались простые признаки `n_events` и
`item_nunique` с Random Forest, как в `quickstart.ipynb`. Расширение до временных,
поведенческих и User-Agent признаков существенно улучшало локальную PR-метрику.

## 6. Результат

По результату отправки решения на проверку:

- **Precision@Recall>=0.70 = 0.81407**
- константный baseline: **0.09391**

Таким образом, фактический результат решения на проверке составляет 0.81407 по основной метрике.

## 7. Воспроизводимость

Среда, в которой решение проверялось:

- Python 3.13.5
- pandas 2.2.3
- numpy 2.3.5
- scikit-learn 1.8.0
- catboost 1.2.8

Запуск из каталога проекта:

```bash
pip install -r requirements.txt
python solution.py
```

На выходе создаётся `submission.csv`.

## 8. Ограничения

Локальная валидация используется для выбора и проверки подхода, а приведённый выше результат
0.81407 — фактический результат отправленного решения. Никаких правил по конкретным `cookie_id`, ручной разметки теста,
внешних API или LLM не используется.
